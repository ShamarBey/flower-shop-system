# Контрольные вопросы лабораторной работы №2

## 1. Query, Path и Request Body

Query-параметры передаются после знака `?` и используются для фильтрации, сортировки и пагинации коллекции: `GET /products?limit=10`. Они не должны менять идентичность ресурса.

Path-параметр является частью URI и однозначно указывает на ресурс: `GET /products/{productId}`. Его используют, когда серверу нужно получить конкретный товар, заказ или черновик.

Request Body содержит структурированные данные запроса, обычно JSON. Он нужен для создания ресурса и передачи сложного набора полей: `POST /orders` или `PATCH /products/{productId}`.

## 2. Идемпотентность HTTP-методов

Идемпотентный запрос после повторного выполнения приводит ресурс к тому же состоянию, что и первое выполнение. `GET` только читает данные, `PUT` полностью задает состояние ресурса, а `DELETE` повторно удаляет уже удаленный ресурс, поэтому эти методы считаются идемпотентными.

`POST` обычно создает новый ресурс при каждом вызове. Повторная отправка `POST /orders` может создать второй заказ, поэтому POST не считается идемпотентным. Для защиты оформления заказа можно использовать idempotency key, но это отдельный механизм.

## 3. Разница между 401 и 403

`401 Unauthorized` возвращается, когда сервер не получил действительный токен: токен отсутствует, просрочен или поврежден. Клиенту нужно пройти аутентификацию.

`403 Forbidden` возвращается, когда пользователь уже аутентифицирован, но его роль не позволяет выполнить операцию. Например, клиент не может создать складское движение, а кладовщик не может изменить системные роли.

## 4. Назначение components/schemas и $ref

`components/schemas` содержит переиспользуемые модели входных и выходных данных: `Product`, `OrderResponse`, `ErrorResponse` и другие. `$ref` ссылается на такую модель из конкретного эндпоинта.

Это уменьшает дублирование YAML, сохраняет единый контракт и позволяет Swagger UI показать структуру запроса или ответа в одном месте. Если схема товара изменяется, ее достаточно обновить один раз.

## 5. PUT и PATCH

`PUT` предназначен для полной замены ресурса. Клиент передает весь объект, а отсутствующие поля могут быть сброшены по правилам API.

`PATCH` предназначен для частичного изменения. Клиент передает только поля, которые нужно обновить. В нашем API `PATCH /products/{productId}` меняет отдельные свойства товара, а `PATCH /orders/{orderId}/status` меняет статус и комментарий.
