## Серверный каркас — лабораторная №3

| Проверка | Результат |
|---|---|
| Python-окружение | Установлено в `.venv`, проверено на Python 3.13.3 |
| Файлы зависимостей | `pip install -r requirements-dev.txt` и `pip install --no-deps -e .` выполнены, `pip check` не нашел несовместимостей |
| `.env` | Локальная копия создана из шаблона, Git игнорирует ее и `.venv` |
| Разделение слоев | API вызывает сервис; сервис не импортирует HTTP, конфигурацию или конкретное хранилище |
| Автотесты | 19 passed: конфигурация, UTF-8, приоритет env, неверные настройки, JSON, uptime и границы слоев |
| Локальный процесс | `.venv/Scripts/python.exe -m flower_shop` запущен на `127.0.0.1:8000` |
| Запрос через curl | `/api/v1/health` возвращает `200 OK`, `application/json` и все пять полей |
| Реальный запрос из Swagger UI | В Chromium нажаты Try it out → Execute; получен 200 с фактическим uptime |
| OpenAPI | Таблица и YAML согласованы: 23 проектные операции, одна реализованная операция в live `/openapi.json` |
| Исключение линтера | Только для health отключено требование обязательного 4XX: у публичного liveness нет параметров, требующих такой ошибки |
| Независимое ревью | Существенных дефектов не обнаружено |

При тестах Starlette выдает предупреждение об устаревании тестового адаптера `httpx`; тесты проходят, работа сервера не затронута. Предупреждение не скрывается.

В лабораторной №3 еще не подключены СУБД, миграции, авторизация, каталог и заказы. Отсутствующие серверные операции возвращают 404. Это соответствует границам каркаса из методички.
