# Use Cases

## UC-01. Создание индивидуального букета

**Актор:** клиент.

**Предусловия:** каталог доступен; клиент открыл конструктор.

**Основной сценарий:**

1. Клиент выбирает размер или базовый шаблон букета.
2. Система показывает доступные категории компонентов.
3. Клиент добавляет цветы, упаковку и дополнительные элементы.
4. Система проверяет количество, совместимость и остаток.
5. Система пересчитывает цену и отображает состав.
6. Клиент сохраняет букет и добавляет его в корзину.

**Альтернативы:**

- компонент недоступен — система предлагает разрешенные замены;
- нарушено правило количества — система показывает причину и допустимый диапазон;
- состав несовместим — оформление запрещается до исправления.

## UC-02. Оформление заказа

**Актор:** клиент.

**Предусловия:** корзина содержит валидный букет или товар.

**Основной сценарий:**

1. Клиент указывает контактные данные.
2. Выбирает доставку или самовывоз.
3. Выбирает дату и временной интервал.
4. Система повторно проверяет наличие в транзакции.
5. Система создает резерв и заказ со статусом `NEW`.
6. Клиент получает номер заказа.

## UC-03. Подтверждение заказа менеджером

**Актор:** менеджер.

1. Менеджер открывает список новых заказов.
2. Проверяет состав, срок и возможность сборки.
3. Подтверждает заказ или предлагает замену.
4. Система переводит заказ в `CONFIRMED` либо возвращает его клиенту на согласование.

## UC-04. Проведение складской операции

**Актор:** кладовщик.

1. Кладовщик выбирает складскую операцию.
2. Указывает товар, количество, причину и документ-основание.
3. Система проверяет допустимость операции.
4. Система изменяет остаток и записывает движение в журнал.

## UC-05. Сборка букета

**Актор:** флорист.

1. Флорист открывает подтвержденный заказ.
2. Видит плановый состав и зарезервированные позиции.
3. Собирает букет.
4. При необходимости выбирает разрешенную замену.
5. Система фиксирует фактический состав и переводит заказ в `READY`.

## UC-06. Отмена заказа

**Актор:** клиент или менеджер.

1. Пользователь запрашивает отмену.
2. Система проверяет допустимость отмены по текущему статусу.
3. Система переводит заказ в `CANCELLED`.
4. Зарезервированный остаток освобождается.
5. Причина отмены сохраняется в истории.
