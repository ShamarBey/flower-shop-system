# Бизнес-правила конструктора и складского учета

## Конструктор букета

1. В каждом букете должен быть хотя бы один основной цветок.
2. Для каждого товара проверяются минимальное и максимальное количество.
3. Компонент может быть помечен как несовместимый с другой категорией или товаром.
4. Недоступный товар нельзя добавить в новый состав, но уже созданный черновик должен показать предупреждение.
5. Цена рассчитывается как сумма строк состава, упаковки и дополнительных услуг.
6. Скидки в учебном контракте пока не поддерживаются; цену определяет сумма компонентов и доставки. Будущее подключение скидок потребует отдельной модели.
7. Разрешенная замена должна принадлежать той же категории либо быть явно указана менеджером.

## Резервирование

1. При оформлении заказа система повторно читает остатки внутри транзакции.
2. Если доступного остатка недостаточно, заказ не создается.
3. После успешного оформления создается `Reservation` с временем истечения.
4. При подтверждении заказа резерв сохраняется до фактической сборки.
5. При отмене или истечении срока резерв освобождается.
6. При списании собранного букета резерв закрывается, а физический остаток уменьшается.

## Статусы заказа

```text
NEW -> CONFIRMED -> ASSEMBLING -> READY -> COMPLETED
CONFIRMED -> NEEDS_APPROVAL -> CONFIRMED
NEW -> CANCELLED
CONFIRMED -> CANCELLED
NEEDS_APPROVAL -> CANCELLED
```

Переходы проверяются backend. Клиент не может самостоятельно перевести заказ в `READY` или `COMPLETED`.

Владелец может отменить NEW и CONFIRMED; менеджер и администратор — также NEEDS_APPROVAL. После начала сборки отмена не поддерживается этим контрактом (409). Флорист может начать сборку подтвержденного заказа и пометить собираемый заказ готовым. Остальные переходы из графа доступны менеджеру и администратору.

При переходе CONFIRMED -> ASSEMBLING компоненты атомарно списываются из физического остатка, резерв закрывается и записывается движение SALE. При подтверждении заказа expires_at продлевается до согласованного срока сборки; потеря Redis не освобождает резерв. Цена заказа определяется историческими ценами строк, а не текущим каталогом.
