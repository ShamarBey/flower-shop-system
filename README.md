# Информационная система цветочного магазина

Информационная система управления заказами и товарными запасами цветочного магазина с интерактивным конструктором букетов.

Проект выполняется как сквозная учебная работа по разработке серверного приложения. Подготовлены архитектура предметной области, REST-контракт OpenAPI 3.0 и запускаемый серверный каркас FastAPI с проверкой здоровья.

## Цель системы

Система должна позволять клиенту собрать индивидуальный букет, сразу увидеть доступность компонентов и итоговую стоимость, оформить заказ и отслеживать его статус. Сотрудники магазина управляют каталогом, запасами, рецептами букетов и обработкой заказов.

## Принятые допущения MVP

- интерфейс — веб-приложение;
- архитектура — модульный монолит;
- backend — FastAPI;
- frontend — Vue 3 + TypeScript;
- база данных — PostgreSQL;
- PostgreSQL хранит остатки и резервы; Redis планируется как кэш;
- поддерживаются доставка и самовывоз;
- онлайн-оплата подключается после базового сценария заказа;
- в MVP используется один склад, но модель данных допускает несколько складов.

## Статус

Лабораторные №1–2 содержат архитектуру и контракт будущего REST API. В лабораторной №3 реализованы серверный каркас, загрузка конфигурации и публичный `GET /api/v1/health`. Каталог, заказы, авторизация, конструктор, хранилище данных и пользовательский интерфейс пока описаны контрактом; их реализация относится к следующим работам.

## Запуск сервера — лабораторная №3

Требуется Python 3.11 или новее. Все команды ниже выполняются в PowerShell из корня репозитория:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
.\.venv\Scripts\python.exe -m flower_shop
```

Если локальный `.env` уже существует, сохраните его настройки и пропустите копирование. Вызов Python по полному пути внутри `.venv` позволяет обойтись без активации окружения.

При стандартных настройках сервер доступен по адресу `http://127.0.0.1:8000`. Откройте `http://127.0.0.1:8000/api/v1/health` в браузере или выполните в другом окне PowerShell:

```powershell
curl.exe -i http://127.0.0.1:8000/api/v1/health
```

Ожидаются `200 OK`, `Content-Type: application/json` и JSON следующего вида. Значение `uptime` растет с момента запуска и выражается в секундах:

```json
{
  "status": "pass",
  "app_name": "Flower Shop API",
  "version": "1.0.0",
  "environment": "development",
  "uptime": 12.34
}
```

Swagger UI работающего сервера: `http://127.0.0.1:8000/docs`; текущая спецификация работающего сервера: `http://127.0.0.1:8000/openapi.json`. Здесь показан реализованный health-check. Автосхема FastAPI использует OpenAPI 3.1, а проектный `openapi.yaml` сохраняет требуемый методичкой стандарт 3.0.3. Остальные операции находятся в проектном YAML. Стандартный интерфейс FastAPI `/docs` загружает ресурсы Swagger из CDN и требует интернета; сам health-check работает без него.

Остановить сервер можно сочетанием Ctrl+C. Для выполнения health-check не нужны PostgreSQL, Redis, Docker или учетная запись пользователя.

## Конфигурация

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `APP_NAME` | Название сервиса в ответе health-check | `Flower Shop API` |
| `APP_VERSION` | Версия сервиса | `1.0.0` |
| `APP_ENV` | Окружение: `development`, `test` или `production` | `development` |
| `HTTP_HOST` | Адрес прослушивания | `127.0.0.1` |
| `HTTP_PORT` | TCP-порт сервера | `8000` |

Шаблон находится в `.env.example`. Приложение читает локальный `.env` из текущего рабочего каталога, поэтому запускайте его из корня проекта. Переменные процесса имеют приоритет над значениями `.env`. Некорректные значения конфигурации останавливают запуск с ошибкой валидации.

`.env` и `.venv` исключены из Git. Шаблон не содержит реальных паролей или токенов; в health-check не добавляются секретные настройки будущих интеграций.

## Просмотр полного проектного API — лабораторная №2

Требуются Node.js 22.14+ и Python. Из корня репозитория один раз установите инструменты по lock-файлу:

```bash
npm ci
```

Запустите статический сервер только на локальном интерфейсе:

```bash
python -m http.server 8080 --bind 127.0.0.1
```

Откройте в браузере `http://127.0.0.1:8080/docs/swagger-ui.html`. Страница загрузит `openapi.yaml`: 22 операции бизнес-контракта из лабораторной №2 и health-check из лабораторной №3, всего 23 операции. Swagger UI установлен локально: после `npm ci` доступ в интернет для просмотра не нужен. Отправка запросов из этой статической страницы отключена, поскольку основная часть API пока существует только как контракт. Остановить статический сервер можно клавишами Ctrl+C.

Статический сервер документации работает на порту `8080`, а FastAPI по умолчанию — на `8000`: их можно запускать одновременно.

## Проверка материалов

Тесты серверного каркаса:

```powershell
.\.venv\Scripts\python.exe -m pytest
```

Проверка документации и спецификации после `npm ci`:

```bash
npm run diagrams
npm run validate
```

ERD строится из `docs/diagrams/erd.dbml` (17 таблиц, 23 связи); ручное редактирование SVG не требуется. Сохраняются SVG и Graphviz DOT с полями, ключами и кратностью. Для перегенерации обеих диаграмм также доступно `python tools/render_diagrams.py` после `npm ci`.

Проверка включает OpenAPI, синтаксис DBML, соответствие таблицы эндпоинтов спецификации, публичность каталога, ссылки документов и состав ERD. [Порядок защиты](docs/defense-checklist.md) описывает, что открыть на сдаче.
